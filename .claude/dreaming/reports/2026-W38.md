## Nit (informational)

### N1. `.env.example` says `TTS_BACKEND=azure` but the comment at the top
of the config block says "Live default since 2026-09-15"

`.env.example:9`: `TTS_BACKEND=azure`, comment "LIVE default since
2026-09-15 (ElevenLabs subscription cancelled)". `cmd/bot/config.go:96`:
`TTSBackend: def("TTS_BACKEND", "elevenlabs")`. **Mismatch.** The default
applied by `LoadConfig` is still `elevenlabs`; the example file ships with
`azure`. A fresh `.env` (no `TTS_BACKEND=` line) will start with
`elevenlabs` and then fail `validate()` because there's no
`ELEVENLABS_API_KEY`. The example is doing the work of "what the demo
actually needs" rather than "what the code defaults to".

Either:
- (a) flip the code default to `azure` (and the `ELEVENLABS_API_KEY` /
  `ELEVENLABS_VOICE_A/B` keys to "commented out by default" — the file
  already says the subscription was cancelled), or
- (b) make the example `TTS_BACKEND=elevenlabs` and keep Azure commented.

Both are reasonable; this is a stylistic call. (a) better matches the
project memory + `.env.example` comment; (b) better matches the code's
own fallback for "no .env at all". Val's call.
